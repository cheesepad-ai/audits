#### 🟢 [L-1] Entire supply minted to deployer creates concentration risk

**Description:**
The constructor mints 100% of `scaledSupply` to `msg.sender`. No vesting, distribution, or lock is applied.

```solidity
uint256 scaledSupply = totalSupply_ * (10 ** uint256(decimals_));
_mint(msg.sender, scaledSupply);
```

**Impact:**
The deployer holds the full supply and can move or sell the entire float at will, exposing holders to a market-dump / single-point-of-failure risk. This is normal for fixed-supply tokens but should be understood by holders.

**Location:**
`CheesePadStandardToken` constructor.

**💡 Recommendation:**
> **Action Required:** Verify off-chain how the deployer distributes the supply (liquidity, team, community). Consider vesting/locking contracts for team allocations and publish the distribution to holders.

#### 🟢 [L-2] Unchecked multiplication overflow potential in supply scaling

**Description:**
`totalSupply_ * (10 ** uint256(decimals_))` is computed in checked arithmetic (Solidity ≥0.8), so an overflow reverts rather than wrapping. However, an extremely large `totalSupply_` combined with `decimals_ = 18` could unexpectedly revert deployment, and there is no explicit sanity bound on `totalSupply_`.

```solidity
uint256 scaledSupply = totalSupply_ * (10 ** uint256(decimals_));
```

**Impact:**
No fund risk (reverts safely), but a misconfigured deployment fails silently for the operator with a generic overflow error.

**Location:**
`CheesePadStandardToken` constructor.

**💡 Recommendation:**
> **Action Required:** Optionally add an explicit upper-bound `require` on `totalSupply_` with a clear revert message to give better deployment feedback. No security change required.

#### 🟢 [L-3] Native fee forwarded via low-level call in constructor

**Description:**
The constructor forwards `msg.value` to `feeReceiver_` using a low-level `call`:

```solidity
(bool ok, ) = feeReceiver_.call{value: msg.value}("");
require(ok, "Fee transfer failed");
```

If `feeReceiver_` is a contract that reverts or consumes excessive gas, deployment fails. The call precedes `_mint`, so no state is corrupted, but a griefing/receiver contract could block deployments to a given fee address.

**Impact:**
Deployment failure only; no reentrancy path is exploitable since minting happens after and there is no other mutable state at that point.

**Location:**
`CheesePadStandardToken` constructor.

**💡 Recommendation:**
> **Action Required:** Acceptable as-is. Ensure `feeReceiver_` is an EOA or a trusted, simple receiver. Optionally allow `feeAmount_ == 0` deployments to skip the external call.

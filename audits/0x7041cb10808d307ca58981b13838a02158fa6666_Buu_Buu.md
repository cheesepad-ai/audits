### High Findings

#### 🟠 [H-1] Whitelist Can Bypass `tradingAllowed` Gate and Fees Pre-Launch

**Description:**
Transfers bypass the `tradingAllowed` gate when either side is fee-exempt. Owner can set any address as exempt via `setExemptFromFee()`, enabling pre-launch buys/sells without fees once liquidity exists.

```solidity
function _transfer(address from, address to, uint256 amount) internal virtual override {
    if (!exemptFromFees[from] && !exemptFromFees[to]) {
        require(tradingAllowed, "Trading not active");
        amount -= handleTax(from, to, amount);
    }
    super._transfer(from, to, amount);
}

function setExemptFromFee(address _address, bool _isExempt) external onlyOwner {
    ...
    exemptFromFees[_address] = _isExempt;
}
```

Exploit scenario: Owner enables liquidity before `enableTrading()`, then exempts a favored address (`exemptFromFees[addr]=true`). That address buys from the pair pre-launch with zero tax, front-running public participants.

**Impact:**
Unfair launch risk; selected addresses can trade ahead of the public and dodge fees.

**Location:**
`Buu._transfer()` and `Buu.setExemptFromFee()`.

**💡 Recommendation:**
> **Action Required:**
> 1. Enforce `tradingAllowed` regardless of fee exemption (add independent trading gate).
> 2. Alternatively, block AMM interactions until `tradingAllowed` is set, even for exempt addresses.
> 3. If intentional, disclose prominently to users in documentation.

### Medium Findings

#### 🟡 [M-1] Centralized Control of Fee Proceeds and Rescues via `mktAddress`/`devAddress`

**Description:**
ETH from fee swaps is split and sent via low-level calls to `devAddress` (40%) and `mktAddress` (60%). Additionally, `mktAddress` alone can withdraw all ETH and rescue arbitrary ERC20 tokens (excluding the project token). These powers persist even if `owner` renounces ownership.

```solidity
(success, ) = devAddress.call{value: devShare, gas: 35000}("");
(success, ) = mktAddress.call{ value: remainingBalance, gas: 35000 }("");

function withdrawStuckBNB() external {
    require(msg.sender == mktAddress, "Not MKT");
    (success, ) = address(mktAddress).call{value: amount}("");
}

function rescueTokens(address _token) external {
    require(msg.sender == mktAddress, "Not MKT");
    require(_token != address(this), "Cannot rescue project token");
    SafeERC20.safeTransfer(IERC20(_token), address(mktAddress), _contractBalance);
}
```

**Impact:**
- Central party can extract all ETH held by the contract and any third-party tokens.
- Post-renounce, these privileges remain, potentially misleading users about decentralization.

**Location:**
`Buu.convertTaxes()`, `Buu.withdrawStuckBNB()`, `Buu.rescueTokens()`.

**💡 Recommendation:**
> **Action Required:**
> 1. Restrict withdrawals/rescues to multisig and/or timelock.
> 2. Emit events and require success on transfers (revert on failure).
> 3. If decentralization is desired post-renounce, consider removing or vesting these functions.

#### 🟡 [M-3] Gas-Stipend (35,000) on Payouts May Fail for Contract Recipients, Locking Distribution

**Description:**
ETH payouts to `devAddress` and `mktAddress` use a 35,000 gas cap. If either is a contract with a non-trivial fallback, the transfer may fail. While `withdrawStuckBNB()` can recover ETH, it sends the full balance to `mktAddress`, not preserving the intended 40/60 split.

```solidity

(success, ) = mktAddress.call{ value: remainingBalance, gas: 35000 }("");
```

**Impact:**
- Failed dev payout; funds accumulate until manual intervention.
- Potential misallocation if `withdrawStuckBNB()` is used (dev share lost to mkt).

**Location:**
`Buu.convertTaxes()`.

**💡 Recommendation:**
> **Action Required:**
> 1. Remove gas cap or add a pull-based claim mechanism for each role.
> 2. Track owed balances in storage; allow roles to withdraw later without gas caps.
> 3. Revert on failed transfer to avoid silent misallocations.

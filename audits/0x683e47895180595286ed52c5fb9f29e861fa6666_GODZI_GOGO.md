GOGO (GODZI) is a BEP-20 tax token deployed on BSC with a 3% buy tax and 3% sell tax routed through PancakeSwap V2. The contract has a fixed total supply of 19,540,000,000,000 tokens (9 decimals), with taxes split 40% to a dev address and 60% to a marketing address. ### High Findings

#### 🟠 [H-1] Owner/Marketing Concentration Enables Fund Drainage and Central Control

**Description:**
The `owner`, `devAddress`, and `marketingAddress` are all the same EOA (`0xa81F...6492`). The `marketingAddress` can drain all contract BNB and rescue any ERC20 held by the contract without restriction.

```solidity
function withdrawStuckBNB() external {
    require(msg.sender == marketingAddress, "Not marketing");
    (success, ) = address(marketingAddress).call{value: address(this).balance}("");
}

function rescueTokens(address _token) external {
    require(msg.sender == marketingAddress, "Not marketing");
    ...
    SafeERC20.safeTransfer(IERC20(_token), address(marketingAddress), _contractBalance);
}
```

`rescueTokens` has no guard preventing rescue of the GOGO token itself, allowing the marketing wallet to sweep any GOGO accumulated in the contract.

**Impact:**
A single compromised or malicious key controls all privileged functions, all accumulated tax funds, and can extract the token's own balance. This is a central point of failure.

**Location:**
`withdrawStuckBNB`, `rescueTokens`; all admin addresses equal at deploy.

**💡 Recommendation:**
> **Action Required:** Separate owner, dev, and marketing roles across distinct wallets (preferably multisigs). Explicitly block rescuing the native GOGO token in `rescueTokens`. Consider timelocks on privileged actions.

#### 🟠 [H-2] Trading Gate Can Permanently Trap Non-Exempt Holders

**Description:**
`_transfer` reverts for all non-exempt addresses until `enableTrading()` is called. Only the owner can enable trading, and there is no time-bound fallback.

```solidity
if (!exemptFromFees[from] && !exemptFromFees[to]) {
    require(tradingAllowed, "Trading not active");
    ...
}
```

**Impact:**
If the owner never calls `enableTrading`, any tokens distributed to non-exempt users are completely non-transferable — a soft honeypot condition entirely at owner discretion. On-chain `tradingAllowed` is currently `false`.

**Location:**
`_transfer`, `enableTrading`.

**💡 Recommendation:**
> **Action Required:** Enable trading promptly and renounce ownership, or add an auto-enable timestamp so holders cannot be indefinitely locked.

#### 🟡 [M-2] Unchecked Low-Level Call Success in Tax Distribution

**Impact:**

**Location:**

**💡 Recommendation:**

#### 🟡 [M-3] No Reentrancy Guard on Swapback During Transfer

**Description:**

**Impact:**
While the gas-limited calls and router behavior reduce practical risk, an external call chain during a state-changing transfer is an anti-pattern that can enable reentrancy if recipients are contracts.

**💡 Recommendation:**

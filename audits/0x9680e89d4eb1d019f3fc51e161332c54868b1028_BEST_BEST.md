### Medium Findings

#### 🟡 [M-1] Unbounded supply multiplication can overflow for large inputs

**Description:**
The constructor scales the raw supply by decimals without bounding `totalSupply_`:

```solidity
uint256 scaledSupply = totalSupply_ * (10 ** uint256(decimals_));
_mint(msg.sender, scaledSupply);
```

Under Solidity 0.8.x this reverts on overflow rather than silently wrapping, so it is not exploitable for inflation. However, a deployer passing a very large `totalSupply_` (combined with high `decimals_`) will cause an unexpected revert, and the paid `feeAmount_` interaction has already partially executed logic before this line. There is no explicit cap or validation on the resulting supply.

**Impact:**
Deployment reverts unexpectedly for large parameter combinations; no clear error message. No fund loss (the whole tx reverts atomically), but poor UX and no guardrail against unintended dust/huge supplies.

**Location:**
`CheesePadStandardToken` constructor, `scaledSupply` computation.

**💡 Recommendation:**
> **Action Required:** Add a sanity bound on `totalSupply_` (e.g. `require(totalSupply_ <= MAX_SUPPLY, "Supply too large")`) and rely on 0.8 checked arithmetic. Document the expected raw-supply units clearly.

### Low Findings

#### 🟢 [L-1] Deployment fee sent to arbitrary receiver via low-level call

**Description:**
The constructor forwards the entire `msg.value` to a caller-supplied `feeReceiver_` using a low-level `call`:

```solidity
(bool ok, ) = feeReceiver_.call{value: msg.value}("");
require(ok, "Fee transfer failed");
```

The receiver is fully attacker/deployer controlled and can be a contract with arbitrary logic executed during deployment. Since no contract state (balances/supply) exists yet at that point and the mint happens afterward, reentrancy is not exploitable, but the pattern is worth flagging.

**Impact:**
Minimal — no reentrancy surface here, but a malicious/reverting receiver can grief deployment. Fee value handling relies entirely on `msg.value == feeAmount_`.

**Location:**
`CheesePadStandardToken` constructor, fee transfer.

**💡 Recommendation:**
> **Action Required:** Consider using a fixed/trusted fee receiver or a pull-payment pattern. Keep the mint after the external call (already done) so no state is reentrancy-exposed.

**Location:**

**💡 Recommendation:**

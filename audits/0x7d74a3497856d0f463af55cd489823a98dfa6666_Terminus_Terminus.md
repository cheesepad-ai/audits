#### 🟡 [M-1] External swap/liquidity calls in transfer path can cause DoS if router/pair malfunctions

**Description:**
`convertTaxes()` is invoked inside `_transfer()` via `handleTax()` when the contract’s token balance exceeds `swapTokensAtAmt`. It performs external calls to the DEX router (`swapExactTokensForETHSupportingFeeOnTransferTokens` and `addLiquidityETH`). Any router/pair malfunction or revert will revert user transfers that trigger `convertTaxes()`, causing a potential denial of service until resolved.

```solidity
function _transfer(address from, address to, uint256 amount) internal virtual override {
    if (!exemptFromFees[from] && !exemptFromFees[to]) {
        require(tradingAllowed, "Trading not active");
        amount -= handleTax(from, to, amount);
    }
    super._transfer(from, to, amount);
}

function handleTax(address from, address to, uint256 amount) internal returns (uint256) {
    if (
        balanceOf(address(this)) >= swapTokensAtAmt &&
        !isAMMPair[from] &&
        lastSwapBackBlock + 1 <= block.number
    ) {
        convertTaxes(); // external router calls here
    }
    ...
}
```

**Impact:**
If Pancake router/pair reverts (router issues, pair paused, unexpected token behavior), normal transfers that trigger swaps will revert, freezing trading for non-exempt users.

**Location:**
`handleTax()` and `convertTaxes()` logic in `Terminus`.

**💡 Recommendation:**
> **Action Required:**
> 1. Add a configurable boolean `swapEnabled` with `onlyOwner` setter to bypass swaps during router issues.
> 2. Wrap router interactions with try/catch and safely skip on failure to avoid cascading reverts.
> 3. Consider a reentrancy guard around `convertTaxes()` and a mutex flag to prevent nested calls.

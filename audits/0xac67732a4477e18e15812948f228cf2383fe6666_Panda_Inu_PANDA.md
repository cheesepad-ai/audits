#### 🟡 [M-1] Buy/Sell taxes never applied because `pair` is hardcoded to `address(0)`

**Description:**
The contract’s tax logic only applies when `from == pair` (buy) or `to == pair` (sell). However, `pair` is set once to `address(0)` and is `immutable`, and transfers to/from `address(0)` are disallowed. Therefore, buy/sell detection never triggers and `buyTax`/`sellTax` are effectively dead code.

```solidity
address public immutable pair;

constructor() {
    // ...
    pair = address(0);
}

function _transfer(address from, address to, uint256 amount) internal {
    // ...
    uint256 fee = 0;
    if (!isExcludedFromFee[from] && !isExcludedFromFee[to]) {
        require(tradingEnabled || from == owner(), "Trading not enabled");
        if (from == pair) {
            fee = (amount * buyTax) / FEE_DENOMINATOR;
        } else if (to == pair) {
            fee = (amount * sellTax) / FEE_DENOMINATOR;
        }
    }
    // fee is always 0 because pair == address(0)
}
```

**Impact:**
- Configured taxes (2% on-chain) never apply; `updateTaxes()` has no effect on runtime.
- `marketingWallet` and `devWallet` never receive fees from transfers.
- Mismatch between documented tokenomics and actual behavior; may mislead users.

**Location:**
`PandaInu` constructor and `_transfer()` pair checks.

> **Action Required:**
> 1. Replace `immutable pair` with a configurable `pair` variable and add an `onlyOwner` setter guarded against misuse:

#### 🟡 [M-2] Trading gate can be selectively bypassed via `isExcludedFromFee`, enabling privileged pre-trading

**Description:**
The `tradingEnabled` gate is enforced only when both `from` and `to` are not excluded from fees. Excluding an address from fees also bypasses the trading gate for that address’s transfers, allowing trading while the public is blocked.

```solidity
if (!isExcludedFromFee[from] && !isExcludedFromFee[to]) {
    require(tradingEnabled || from == owner(), "Trading not enabled");
    // ...
}
```

**Impact:**
- Owner can allow selected addresses to trade before enabling global trading.
- Potentially unfair launch dynamics (pre-allocation distribution, early sells/buys).

**Location:**
`_transfer()` trading gate condition.

**💡 Recommendation:**
> **Action Required:**
> 1. Enforce the trading gate regardless of fee-exclusion status:
> 
> ```solidity
> require(tradingEnabled || from == owner(), "Trading not enabled");
> ```
> 
> 2. If exclusions are needed for system contracts only, constrain `setExcludedFromFee()` to a fixed allowlist of known addresses (e.g., the token contract, liquidity pair).
> 3. Transparently disclose any pre-trading policy and publish an allowlist before launch.
